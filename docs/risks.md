# elads risk register

Living document. Severity reflects impact × likelihood on the **Raspberry Pi 5** target.

| # | Risk | Sev | Mitigation |
|---|------|-----|-----------|
| R1 | **GL version wall.** SLADE `master` needs desktop GL 3.3, UDB needs GL 3.2 core, but the Pi 5 V3D driver caps desktop GL at **3.1** (compat 2.1). | **High** | Build the **GLES 3.1** render-backend abstraction as the primary path from Phase 1; never hard-depend on desktop GL 3.3. Validate the GLES context on-device in **Phase 0**. Keep Zink-over-Vulkan and `llvmpipe` as documented fallbacks. |
| R2 | **Renderer rewrite is large.** SLADE/UDB code carries immediate-mode, display lists, `GL_QUADS`, fixed-function fog, `GL_POINT_SPRITE`, double-precision verts — none valid under GLES. | **High** | Confine all GL to one abstraction layer; lower legacy idioms to shader triangles / `gl_PointCoord` / UBO fog / float. Reuse GZDoom's GLES backend as the reference. Phase the 3D visual mode so only 2D+gfx must work for MVP. |
| R3 | **UDB-level 3D fidelity** (slopes, 3D floors, dynamic lights, shadowmaps, models) is the most code-heavy part and stresses V3D fill-rate. | **High** | Stage strictly: textures+light+fog (v1) → slopes → 3D floors → capped forward light list (later). Ship real-time shadowmaps off by default. Treat UDB as a reference, not a parity gate for release. |
| R4 | **Sector triangulation** on real-world maps (self-intersections, islands/holes, unclosed sectors) is a correctness minefield. | Med | Use `earcut.hpp`/libtess2 with outer-CW/inner-CCW loop convention and hole support; cache per-sector VBOs and re-triangulate only on edit; port SLADE's guard heuristics as validation. |
| R5 | **wxAUI idle model** starves an always-rendering GL canvas (documented SLADE-class friction). | Med | Add explicit idle handling / decouple canvas repaint from wxAUI idle, as SLADE does; validate docked live viewports early on both Wayland/labwc and X11. |
| R6 | **wxWidgets 3.3 vs distro 3.2.x.** SLADE `master` wants wx ≥ 3.3.1; building wx from source on the Pi is slow. | Med | Target **system wx 3.2.9+** (has EGL 1.4 + HiDPI GL fixes); `BUILD_WX=OFF`. Confirm on-device with `apt-cache policy libwxgtk3.2-dev`. Backport only the wx APIs elads truly needs. |
| R7 | **GZDoom needs a live GL context** (no built-in headless compile-validate mode). | Med | Interactive playtest on an attached display for users; for CI/validation set up an **offscreen EGL** context, and rely on parsing GZDoom's `-stdout` compile logs. |
| R8 | **No mature ZScript/DECORATE/ACS language server**; semantic features must be built in-house. | Med | Ship data-driven keyword highlighting + calltips (SLADE model) for v1; use out-of-process **GZDoom as the authoritative validator**; defer tree-sitter/LSP to Phase 4. |
| R9 | **GPLv3 propagation.** Forking SLADE + combining with GPLv3 references forecloses closed-source distribution. | Low | Commit to GPLv3 open source up front. SLADE is GPLv2-**or-later** so the combination is lawful; keep third-party tools as separate-process invocations where license hygiene matters. |
| R10 | **Debian t64 ABI renames** make a single `.deb` non-portable across bookworm/trixie. | Low | Build one `.deb` per Pi OS release via CPack with SHLIBDEPS; add a Flatpak for the cross-distro long tail. |
| R11 | **Thermal throttling** (soft 80 °C / hard 85 °C) degrades sustained GPU+CPU load. | Low | Specify the official **Active Cooler + 27 W PD** supply in the hardware BOM; benchmark 3D mode under sustained load. |
| R12 | **AJBSP upstream pinning.** The canonical standalone AJBSP repo is not on GitHub search; the build script uses a mirror. | Low | Verify/pin the AJBSP source in Phase 0 (mirror `RusticTroll/ajbsp`, or the maintained `elf-alchemist/elfbsp`). ZDBSP alone covers GZDoom's node needs, so AJBSP is non-blocking. |
